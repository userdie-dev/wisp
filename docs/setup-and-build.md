# Разработка и сборка

## Ограничение: без Rust локально

На машине разработчика **не устанавливается** Rust/Cargo. Это значит:

- Локально можно разрабатывать и проверять **только фронтенд** (`src/`) через Vite — без Tauri-рантайма. `invoke()` в этом режиме будет падать/недоступен; фронтенд-код должен быть терпим к отсутствию `window.__TAURI_INTERNALS__` (см. `src/lib/tauri-env.ts`).
- Rust-часть (`src-tauri/`) не компилируется и не проверяется (`cargo check`/`cargo build`) на машине разработчика — только читается/пишется как текст.
- Полная сборка приложения (Tauri + Rust + бандл под конкретную ОС) происходит **исключительно на GitHub Actions** — см. `.github/workflows/build.yml`.

Практическое следствие: после любых изменений в `src-tauri/` нужно закоммитить и посмотреть на прогон workflow в GitHub Actions (вкладка Actions репозитория), прежде чем считать изменения рабочими. Компилятор Rust на CI — единственный источник правды по корректности Rust-кода в этом проекте.

## Локальная разработка фронтенда

```bash
pnpm install
pnpm dev
```

Поднимет Vite dev server. UI откроется в обычном браузере — окно не будет прозрачным/размытым (это эффект нативного окна Tauri), вкладки не будут показывать реальные веб-страницы (нет дочерних веб-вью), но вёрстку, тему, роутинг между История/Закладки/Настройки, состояние Pinia — всё это можно смотреть и итерировать без Tauri.

## Сборка на GitHub Actions

Workflow `.github/workflows/build.yml`:

- триггерится на `push` в `main`, на pull request (только `cargo check` + фронтенд build, без паблиша) и на тег `v*` (полная сборка + релиз).
- матрица ОС: `windows-latest`, `macos-latest`, `ubuntu-latest` — получаем нативные бинарники под все три платформы одним прогоном.
- использует официальный `tauri-apps/tauri-action`, который сам ставит Rust-тулчейн и системные зависимости (WebView2 на Windows уже есть в раннере, `libwebkit2gtk` на Linux ставится шагом `apt-get`) — на раннере GitHub, не на машине разработчика.
- на тег `vX.Y.Z` publish создаёт GitHub Release с артефактами (`.msi`/`.exe` для Windows, `.dmg`/`.app` для macOS, `.deb`/`.AppImage` для Linux).

Как выпустить сборку:

```bash
git tag v0.1.0
git push origin v0.1.0
```

Это единственный способ получить установочные файлы — сборка **runs on GitHub, never locally**.

## Проверка на PR

На pull request'ах workflow гоняет:

1. `pnpm install && pnpm build` — проверка, что фронтенд собирается и типы (`vue-tsc`) проходят.
2. `cargo check --manifest-path src-tauri/Cargo.toml` — проверка, что Rust-код компилируется, без полной сборки бандла (быстрее).

Это заменяет локальную проверку `cargo build`, которую разработчик выполнить не может.
