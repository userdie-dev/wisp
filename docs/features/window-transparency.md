# Прозрачное окно и блюр

## Конфигурация окна

`src-tauri/tauri.conf.json`, окно `main`:

```json
{
  "transparent": true,
  "decorations": false,
  "titleBarStyle": "Overlay"
}
```

- `decorations: false` — убираем нативную рамку/заголовок, рисуем свой drag-region через атрибут `data-tauri-drag-region` на корневых элементах тулбара и сайдбара (требует разрешения `core:window:allow-start-dragging` в `capabilities/default.json`). **Не** через CSS `-webkit-app-region: drag` — на Windows/WebView2 вложенные "no-drag" элементы (кнопки, инпут омнибокса, кнопки управления окном) ненадёжно исключаются из drag-региона и перестают получать клики в собранном приложении, хотя в браузере при `pnpm dev` и на macOS (WKWebView) всё работало. `data-tauri-drag-region` — обычный DOM-обработчик mousedown на точном элементе, а не OS-level hit-testing, поэтому этой проблемы не имеет ни на одной платформе.
- `titleBarStyle: "Overlay"` — на macOS оставляет системные traffic-light кнопки поверх нашего контента (нужно отступить от них в CSS сайдбара: `padding-top` с учётом `env(titlebar-area-height)` / фиксированные ~28px).
- `transparent: true` на macOS требует ещё двух вещей, без них прозрачность не включится: `"macOSPrivateApi": true` в `app` (не только в `windows[]`) и Cargo-фича `macos-private-api` на зависимости `tauri` (`src-tauri/Cargo.toml`) — уже настроено в этом проекте.

## Реальный блюр (vibrancy), не просто CSS

Полупрозрачный `background: rgba(...)` в CSS не даёт блюра того, что находится **за окном** (рабочий стол/другие окна) — это системная фича композитора. Используем crate **window-vibrancy**, применяется один раз в Rust при старте окна (`src-tauri/src/main.rs`, хук `setup`):

| Платформа | Функция | Эффект |
|---|---|---|
| Windows 11 | `apply_acrylic` (fallback `apply_blur` на Win10) | Acrylic-блюр |
| macOS | `apply_vibrancy(.., NSVisualEffectMaterial::Sidebar, ..)` | системный vibrancy-материал |
| Linux | — не поддерживается `window-vibrancy` | окно остаётся просто прозрачным (без блюра), см. «Известные ограничения» |

## Где именно прозрачность/блюр применяется в UI

Не всё окно однородно прозрачное — см. схему в [architecture.md](../architecture.md):

- **Сайдбар** (вкладки) и **тулбар** (омнибокс) — полупрозрачный фон поверх системного блюра (`bg-black/30 dark:bg-black/40` и т.п. через Tailwind), чтобы текст оставался читаемым на любом фоне рабочего стола.
- **Область контента** — полностью `background: transparent`, потому что физически это место, где поверх chrome-веб-вью показывается дочерний content-веб-вью активной вкладки (см. [tabs.md](./tabs.md)). Если бы эта область не была прозрачной, дочерний веб-вью либо просвечивал бы неправильно, либо перекрывался.
- Когда открыта внутренняя страница (История/Закладки/Настройки) вместо вкладки, эта область временно получает непрозрачный фон темы (см. [theme-settings.md](./theme-settings.md)), так как в этот момент под ней нет дочернего веб-вью с реальным контентом.

## Известные ограничения (этап 1)

- Linux: нет блюра (только прозрачность), зависит от компоновщика окон пользователя (KWin/Mutter с включённым blur-эффектом может дать блюр «бесплатно» на уровне композитора, но это не гарантируется и не контролируется приложением).
- Windows 7/8: `apply_blur` — более старый и грубый эффект, чем Acrylic; не приоритет.
