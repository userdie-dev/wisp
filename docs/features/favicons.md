# Фавиконки

Часть [roadmap](./roadmap.md) → «Рекомендуемый порядок», пункт 1. Только фронтенд.

## Что делает

У вкладок в сайдбаре (а также в [истории](./history.md) и [закладках](./bookmarks.md), куда
`favicon` попадает вместе с записью) вместо серого кружка показывается иконка сайта.

## Подход: соглашение `/favicon.ico`

Дочерние webview вкладок открывают произвольные внешние URL и **не получают** Tauri IPC —
надёжно вытащить `<link rel="icon">` из чужой страницы (инъекция скрипта + обратный вызов в
бэкенд) для внешнего контента нельзя, а `fetch` HTML из chrome-webview блокируется CORS.

Поэтому фавиконка **угадывается** по адресу: [`faviconFor(url)`](../../src/lib/favicon.ts)
возвращает `` `${new URL(url).origin}/favicon.ico` `` для `http(s)`-адресов и `null` для
всего остального (внутренние страницы, стартовая страница, битый URL).

- [`stores/tabs.ts`](../../src/stores/tabs.ts) вызывает `faviconFor` в обработчике
  `tab-updated`, когда меняется `url` вкладки.
- [`TabItem.vue`](../../src/components/sidebar/TabItem.vue): `<img @error>` → эмитит
  `favicon-error` → `Sidebar.vue` зовёт `tabs.clearFavicon(id)` → снова серый кружок
  (сайт без `/favicon.ico`).
- `SavedTab` в `session.json` уже персистит `favicon` — угаданное значение переживает
  перезапуск.

## Не входит

- Разбор реального `<link rel="icon">` / `<link rel="apple-touch-icon">` со страницы.
- Кэш фавиконок на диске, поддержка `data:`-иконок, `.svg` с приоритетом.
- Обращение к сторонним favicon-сервисам (приватность, работа офлайн).
