# Восстановление сессии

Первый пункт [roadmap](./roadmap.md) → «Рекомендуемый порядок». Только фронтенд.

## Что делает

При запуске приложение может восстановить набор вкладок и активную вкладку из
прошлой сессии — вместо того чтобы всегда открывать одну пустую новую вкладку
(поведение этапа 1, см. [tabs.md](./tabs.md), «не входит в первый этап»).

## Настройка «При запуске»

`settings.json` → ключ `startupBehavior`:

| значение    | поведение                                                        |
|-------------|-----------------------------------------------------------------|
| `restore`   | восстановить вкладки и активную вкладку из прошлой сессии (**по умолчанию**) |
| `newTab`    | открыть одну пустую новую вкладку ([стартовую страницу](./start-page.md)) |

UI — секция «При запуске» в Настройках (`src/components/settings/StartupSettings.vue`),
радиогруппа в стиле [ThemeSettings](../../src/components/settings/ThemeSettings.vue).

> Отдельная «домашняя страница» (свой URL) в roadmap упомянута, но в приложении
> сейчас нет настраиваемого homepage-URL — «домашняя страница» и «новая вкладка»
> для системного webview совпали бы. Добавится вместе с настройкой homepage.

## Хранение сессии

Отдельный файл `session.json` (`plugin-store`), ключ `session`:

```ts
interface SavedSession {
  tabs: SavedTab[]
  activeTabId: string | null
}
interface SavedTab {
  id: string
  url: string
  title: string
  favicon: string | null
  pending: boolean       // pending-вкладка (пустая, на стартовой странице)
  createdAt: number
}
```

Пишется из `stores/tabs.ts` по `watch([tabs, activeTabId], …, { deep: true })`
после того как восстановление завершено (`ready === true`) — тот же приём, что в
[history.ts](../../src/stores/history.ts). `loading` и `unloaded` (см. ниже) не
сохраняются — при следующем запуске они вычисляются заново.

## Поток восстановления (`tabsStore.restoreSession()`)

Вызывается из `App.vue` `onMounted` **до** фолбэка «создать пустую вкладку».

1. `await settings.loaded` — дождаться загрузки `startupBehavior` из `settings.json`.
2. Прочитать `session` из `session.json`.
3. Если `startupBehavior !== 'restore'`, сессия пустая или вкладок нет →
   `ready = true`, выход (дальше `App.vue` создаёт пустую вкладку).
4. Иначе для каждой `SavedTab` — добавить `Tab` в стор с
   `unloaded: !pending` (нативный webview ещё не создан) и `loading: false`.
5. Активировать сохранённую активную вкладку (если её id пропал — последнюю).
6. `ready = true` — со следующего тика включается автосохранение.

### Ленивое создание webview (`Tab.unloaded`)

Восстановленные непустые вкладки помечаются `unloaded: true` и **не** создают
дочерний Rust-webview сразу — иначе восстановление 15 вкладок = 15 нативных
webview за один тик на старте. `activateTab(id)` для `unloaded`-вкладки сначала
делает `invoke('tabs_create', { id, url })` и снимает флаг, затем обычный
`tabs_activate`. Фоновая `unloaded`-вкладка так и висит без webview, пока на неё
не переключатся — как «спящие» вкладки в Chrome/Edge.

Вне Tauri (`pnpm dev`) webview нет вообще: восстановленные вкладки видны в
сайдбаре, в области контента — пусто (как и у любой непустой вкладки в dev-режиме).

## Не входит

- Восстановление истории навигации внутри вкладки (back/forward stack) — webview
  создаётся заново с последним URL.
- Восстановление позиции прокрутки и состояния форм на странице.
- Настраиваемый homepage-URL и вариант `startupBehavior: 'homepage'`.
- Восстановление после аварийного завершения с диалогом «восстановить вкладки?».
- Группы вкладок / несколько окон.
